Homework 1：Recursion

1. 解題說明

Problem 1：Ackermann Function

問題描述：

本題要求根據 Ackermann 函數的數學定義，分別使用遞迴與非遞迴方式完成計算。

解題策略：

遞迴版本直接依照三個條件進行判斷：

當 m = 0，回傳 n + 1。

當 n = 0，呼叫 A(m-1,1)。

其他情況，呼叫 A(m-1,A(m,n-1))。

非遞迴版本使用陣列模擬堆疊，利用 while 迴圈依序完成尚未處理的計算。

Problem 2：Powerset

問題描述：

給定集合 S，使用遞迴方式找出全部的子集合。

解題策略：

使用一個陣列記錄每個元素是否被選擇，0 代表不選，1 代表選擇。

每次遞迴分成兩種情況，直到所有元素都處理完成，再輸出子集合。

3. 效能分析

Problem 1：Ackermann

時間複雜度：

Ackermann 函數的成長速度非常快，執行時間取決於 m 和 n 的數值。若使用一般遞迴計算，重複呼叫的次數可能非常龐大。

無法簡單地以固定次數的迴圈或一般多項式時間複雜度描述。

空間複雜度：

遞迴版本需要函數呼叫堆疊，隨著遞迴深度增加，記憶體需求也會增加。

非遞迴版本使用固定大小的陣列模擬堆疊，因此宣告的陣列空間為 O(1)，但容量有限，並不適用於所有輸入。

Problem 2：Powerset

時間複雜度：

假設集合共有 n 個元素，每個元素有選與不選兩種情況，因此會產生 2^n 個子集合。

由於每個子集合輸出時最多需要檢查 n 個元素，因此本程式的總時間複雜度為：

O(n × 2^n)

空間複雜度：

需要使用陣列記錄選擇狀態，並透過遞迴處理 n 個元素，因此額外空間複雜度為：

O(n)

5. 申論及開發報告

Problem 1

Ackermann 函數適合使用遞迴，因為函數的定義本身就是透過重複呼叫來完成計算。

遞迴版本程式碼較短，也比較容易對照數學公式。

非遞迴版本則使用陣列模擬堆疊，讓程式不用自行呼叫函數，也能完成相同的計算流程。

透過這兩種實作方式，可以了解遞迴與堆疊之間的關係。

Problem 2

Powerset 使用遞迴的原因，是因為每個元素都有選與不選兩種可能。

透過遞迴可以依序列舉全部組合，程式也比較容易理解。

本次使用普通陣列儲存元素的選擇狀態，不需要使用額外的容器函式庫。

透過這題可以理解遞迴列舉與子集合產生的概念。
